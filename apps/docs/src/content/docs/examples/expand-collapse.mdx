This example demonstrates a collapsible tree diagram. Each node with children shows a toggle button — collapsing a node hides its whole subtree using the model-level [`hidden`](/docs/guides/conditional-visibility/) flag, and ELK.js re-layouts the remaining visible nodes.

## Additional Explanation

### Key Concepts

- **Hiding with the `hidden` flag:** Collapsing a subtree sets [`hidden`](/docs/api/types/model/simplenode/#hidden) on its nodes in one [`updateNodes`](/docs/api/services/ngdiagrammodelservice/#updatenodes) call. Edges never need their own flag — an edge is effectively hidden whenever one of its endpoint nodes is hidden. Hidden elements are excluded from hit-testing, selection, `zoomToFit` bounds and measurement waits, so no CSS workarounds are required.
- **Layout on the visible set:** The ELK layout pass only receives visible nodes and edges, so a collapsed tree stays compact. Hidden nodes keep their geometry and re-measure automatically when expanded again.
- **Measured before hidden:** Every node is visible in the initial model, so all of them are measured by the time the diagram initializes. The subtrees flagged `collapsed` in the data are hidden right after, in the same transaction as the first layout. This way each node has a real size for every layout pass, whatever its content. Nodes that are already `hidden` in the initial model stay hidden, but a hidden node is never measured. If you want to keep hidden nodes in your model, give each of them a `size` (the measured size replaces it once the node is shown) and flag its parent as `collapsed`. Without a size, the layout has no dimensions for the node when it is expanded and you need workarounds in code.
- **Layout first, then one transaction:** When a subtree is toggled, the layout for the new set of visible nodes is computed first. The collapsed flag, the subtree's `hidden` flags and the new positions are then committed in a single [`transaction`](/docs/guides/transactions/), so nodes that appear are rendered at their final position right away.
- **Fresh reads after awaited updates:** Right after an awaited update, the `nodes()`/`edges()` signals may not have refreshed yet — the layout service reads through [`getModel()`](/docs/api/services/ngdiagrammodelservice/#getmodel) for the latest committed state (see [State Management](/docs/guides/state-management/)).
- **Keeping `hasChildren` in sync:** The [`edgeDrawEnded`](/docs/api/types/events/edgedrawendedevent/) and [`selectionRemoved`](/docs/api/types/events/selectionremovedevent/) events update the `hasChildren` flag as the user draws or deletes edges, so toggle buttons appear and disappear accordingly.
