This example shows line jumps: where two orthogonal edges cross, the horizontal edge jumps over the vertical one. This makes it clear which lines are connected and which only cross.

Move the nodes or draw new edges - the jumps follow the edges. Use the **Arc** and **Gap** buttons to switch between a bridge over the crossed line and a simple break in the line.

## Additional Explanation

The jumps come from a custom routing, `LineJumpsRouting`:

- `computePoints` returns simple orthogonal points between the ports. The points have no jumps, so labels, relink handles and the crossing search work on clean lines.
- `computeSvgPath` draws the path from these points. For each horizontal segment it finds the vertical segments of all edges that cross it, and adds a jump at each crossing. Crossings that are too close for separate jumps share one wider jump.
- `computePointOnPath` places labels along the segments of the path.
- The routing gets the `edges` signal from [`NgDiagramModelService`](/docs/api/services/ngdiagrammodelservice/) and the `config` signal from [`NgDiagramService`](/docs/api/services/ngdiagramservice/). In this example the edge reads these signals while it draws its path, so the jumps update when any edge moves or when the options change.

### Options

Set the options in the config under the routing name:

```typescript
edgeRouting: {
  'line-jumps': { size: 16, style: 'arc' },
},
```

- `size` - the width of a jump in pixels.
- `style` - `'arc'` draws an arc over the other line, `'gap'` breaks the line instead.

To change the options at runtime, call [`updateConfig()`](/docs/api/services/ngdiagramservice/#updateconfig), as the buttons in this example do. The `config` argument of `computeSvgPath` does not cause a redraw, so the routing reads the options from the `config` signal.

### Large Diagrams

The routing stays fast even with thousands of edges:

- All edges share one list of vertical segments, sorted by `x`. The list is built once per model change, not once per edge.
- Each horizontal segment uses a binary search to check only the vertical segments in its own `x` range.
- When the segments and the jump options do not change, for example on pan, zoom or selection, the edges do not redraw their paths.

### Key Concepts

- Implementing the [`EdgeRouting`](/docs/api/types/routing/edgerouting/) interface
- Registering the routing with [`NgDiagramService.registerRouting()`](/docs/api/services/ngdiagramservice/#registerrouting) in the `diagramInit` handler, and making it the default with [`setDefaultRouting()`](/docs/api/services/ngdiagramservice/#setdefaultrouting)
- Adding the edges after the routing is registered, so they use it from the first render
- Passing routing options through the [`edgeRouting`](/docs/api/types/configuration/flowconfig/#edgerouting) config and changing them with `updateConfig()`

The points in this example are kept simple and do not go around nodes. To use jumps with your own paths, keep the `computeSvgPath` part and compute your own orthogonal points.
